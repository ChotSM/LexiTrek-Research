LEXITREK: FIRST WORKING PILOT (1.0.0)
Prepared for ChotSM/LexiTrek-Research, 17 November 2026.

START HERE

Your vocabulary folders are already in GitHub. This package adds the app.

1. Extract LexiTrek_App_Starter.zip on your computer.
2. Open https://github.com/ChotSM/LexiTrek-Research and select Code.
3. Click the small + next to Go to file, then Upload files.
4. Open the extracted package. Drag its six files and the docs folder into
   GitHub. Drag the contents, rather than the outer package folder or ZIP.
5. Confirm that index.html appears at the top level alongside data, docs
   and schemas. Your existing data and teaching documents stay in place.
6. Enter the commit message: Add first working LexiTrek learner app
   Commit directly to main, then click Commit changes.
7. Open repository Settings. If it is hidden, click More, then Settings.
8. Choose Pages in the left sidebar. Under Build and deployment, set:
      Source: Deploy from a branch
      Branch: main
      Folder: / (root)
   Click Save.
9. Allow up to 10 minutes. Return to Settings > Pages and click Visit site.
   Expected address: https://chotsm.github.io/LexiTrek-Research/
10. Try Start my first quest. After the app shows Ready offline, reopen
    that same website address without an internet connection to try it.

If you see a 404, check that index.html is in the repository root and Pages
uses main and / (root). If the word bank will not open, check that the
original data/lexitrek-vocabulary.json and data/example-quest.json exist.
Opening index.html by double-clicking it is not supported: use the website.

WHAT EACH NEW FILE DOES

index.html             Opens the app and loads its layout and code.
styles.css             Controls colours, spacing and screen sizes.
app.js                 Runs the word bank, quest and saved progress.
service-worker.js      Saves the app and two data files for offline use.
app-icon.svg           The LexiTrek compass icon.
manifest.webmanifest   Defines the app name, icon and launch address.
docs/APP_START_HERE.txt This guide.

The ZIP contains app additions only. It relies on your existing data folder.
It does not replace your README, workbook, reservoir, schema or other guides.

FIRST TEST

1. Open Word bank. It should report 235 learning records and nine themes.
2. Search for recycle. Open its card to see a meaning, example and source.
3. Open My quest. Study the five words in A greener school.
4. Try the meaning questions and typed recall. Try a hint on one word.
5. Write two sentences and mark at least two words that you used.
6. Finish. My progress shows practice results and your saved message.
7. Refresh. Your progress should still appear on the same browser/device.
8. Download my learning record creates a JSON file for teacher review.
9. When Ready offline appears, disconnect and reload the website.
10. Try the word search and quest while offline.

TEACHING AND RESEARCH NOTES

Scope: one complete quest, plus the full 235-record searchable reservoir.
The nine themes are available for exploration; there are not nine complete
quests yet. This is a pilot for review, not a finished research instrument.

Vocabulary objectives in the first quest:
V1: choose meanings using contexts.
V2: type a target word from a meaning cue.
V3: write a useful message for a chosen school place.
V5: try delayed recall with proposed reviews on days 1, 3, 7 and 14.
V4 word relationships can be explored in word details where the source
supplies them; dedicated relationship assessment is not yet implemented.
Exact alignment with thesis objectives still needs the thesis text.

Keller's ARCS model informs this design:
Attention: begin with a jar-and-paper problem, then vary the activities.
Relevance: choose a familiar school place and write a useful message.
Confidence: see clear goals and examples; use hints and retry questions.
Satisfaction: complete a message, inspect specific practice results and
share writing with a teacher for meaningful feedback.

Reference: Keller, J. M. (1987). Development and use of the ARCS model of
instructional design. Journal of Instructional Development, 10(3), 2-10.
https://doi.org/10.1007/BF02905780
This design does not establish the app's effectiveness or validate its
optional reflection questions. The ARCS prompts and review intervals are
proposals for piloting; they are not prescribed by the source vocabulary.

Assessment limits:
- Meaning answers are scored by the authored answer key.
- Typed recall compares the target word after trimming spaces and ignoring
  letter case. Other words, inflections and spelling variants are not
  automatically accepted. Inspect the actual response in the export.
- First attempts, retries and first-letter hints are logged. A retry follows
  feedback revealing the answer, so it is recorded as supported practice.
  The score uses only the first answer to each question; recall with support
  is reported separately from first-attempt recall without a hint.
- A completion badge records finishing the activities, not mastery.
- Writing is stored without automatic semantic or grammar grading. Selecting
  two words is a learner self-check, not proof of appropriate use. A teacher
  must check the number of sentences, intended meaning and language form.
- Optional reflection answers use 1-5 and may be left blank. They are newly
  authored pilot prompts, not a validated questionnaire.

Retention:
Review dates are measured from the first completed quest on this browser.
Early extra recall practice is logged without marking a future review done.
Scheduled reviews are marked when started on or after their scheduled time.
Replaying the main quest updates the displayed message and practice score,
while preserving the original review schedule and earlier attempt logs.

Saving:
No accounts, server database, class dashboard or cross-device synchronisation
are included. Writing and progress are kept in this browser's local storage.
On a shared device, the next user may see the same record. Download the
record, then clear progress in My progress before another pupil uses it.
Browser data removal also removes the saved progress and offline copy.
The export contains the message, marked words, optional reflections, each
practice response, hint use, expected answers and timestamps. It contains
no requested pupil name. The teacher needs to arrange record collection.

Offline use:
Open the published HTTPS website online once on each browser/device and wait
for Ready offline. This confirms that the offline resources have been saved.
If the browser blocks service workers or storage, use the app online.
The browser can remove cached files; reopen online if offline loading fails.

DEVELOPER NOTE

Buildless HTML, CSS and JavaScript; no dependency installation is needed.
All asset/data paths are relative, so GitHub project Pages paths work.
Teaching data is read from the two existing data JSON files. The repository
reservoir remains the source of truth. No external fonts, trackers, APIs or
remote image dependencies are used.
For future asset changes, update the cache version in service-worker.js.
When changing the stored data structure, migrate existing local records or
change STATE_VERSION deliberately. Keep existing records for research use.
