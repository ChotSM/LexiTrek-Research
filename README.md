# LexiTrek: Welcome Island quest rehearsal

The opening lesson is a four-stop treasure hunt: label the crew’s feelings, rebuild word signals, sort messages and mark the route to a hidden cove. Each stop explores two words, includes brief written recall and awards a map piece. Pupils choose their route, receive word-specific feedback, and can save for a break. The same grouped-quest engine supports the eight lesson plans.

This is release **2.1.0-quest-rehearsal.1**. It changes task presentation, supported task types, within-lesson ordering and the introduction-session recall balance. Read [the gameplay redesign and ARCS mapping](docs/GAMEPLAY_REDESIGN.md). Research approval and timing evidence must be renewed before freezing this version. ## Run and test

This is a static HTML/CSS/JavaScript app with no installation dependencies. Publish the repository root through GitHub Pages, then open the resulting HTTPS address. Do not double-click index.html. On a workstation with Node available, run `npm test` for the domain and offline-worker tests.

The app starts in rehearsal. Use Teacher to export the candidate register, inspect the eight-lesson plan and rehearse the observation forms. Rehearsal exports are explicitly labelled and rejected by the research merger.

## Research boundaries

- O1/O2/O3 remain externally administered independent assessments. No primary test questions, scoring keys, pupil outcomes or proposal document are published here.
- The intended outcome construct is written form recall plus meaning recall. Practice feedback and completion are not primary outcomes or evidence of mastery.
- ARCS is represented through design and observer records. There is no student motivation questionnaire or automated motivation score.
- O2 is scheduled 24–48 hours after S8. O3 is targeted 28 days after O2, with a documented 26–30-day window.
- Ending S8 pauses the target-word activities. There are no post-S8 study-word reminders, replay buttons or assigned home reviews.
- The prototype uses local behavioural controls, not server authentication or tamper-proof access restrictions. Formal deployment requires the approved managed-device arrangement and a school-device pilot.
- One coded learner uses one research browser run. Shared/staggered workstations need separate managed browser profiles/runs; they have not been validated as a main-study procedure.
- No inferential treatment p-values are generated from the two-class implementation records.
